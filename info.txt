## 2. API Endpoints (`server.py`)

Your service exposes 3 dedicated HTTP POST endpoints for distinct image generation patterns:

1. **`POST /generate/single`** (1 Prompt $\rightarrow$ 1 Image)
* Accepts a single prompt and optional `steps` / `seed`.
* Generates a single output artifact and returns its S3 presigned URL.


2. **`POST /generate/batch`** (1 Prompt $\rightarrow$ N Seed Variations)
* Accepts a single prompt and `num_images` (e.g., 6).
* Generates $N$ distinct variations by assigning incremental CUDA seeds (`seed_base + i`) per iteration.


3. **`POST /generate/multi-prompt`** (N Prompts $\rightarrow$ N Unique Images/Styles)
* Accepts a list of distinct prompts (`prompts: [...]`).
* Renders 1 image per prompt style using an independent random CUDA seed for each item in the list.

## 3. Model Specifications & AI Architecture

Your pipeline combines three distinct machine learning models into a unified inference graph:

```
                  ┌──────────────────────────────────────────┐
                  │   Base SDXL 1.0 (FP16 UNet + Text Enc)   │
                  └────────────────────┬─────────────────────┘
                                       │
                         [pipe.load_lora_weights()]
                                       ▼
                  ┌──────────────────────────────────────────┐
                  │ SDXL-Lightning 4-Step Distillation LoRA  │
                  └────────────────────┬─────────────────────┘
                                       │
                                [pipe.fuse_lora()]
                                       ▼
 ┌────────────────────────┐    ┌─────────────────────────────┐
 │ FP16 VAE Fix           ├───►│ Fused Execution Graph       │
 │ (madebyollin)          │    │ (Euler Discrete Scheduler)  │
 └────────────────────────┘    └─────────────────────────────┘

```

### Component Breakdown

* **Base Pipeline Model:** `stabilityai/stable-diffusion-xl-base-1.0`
* **Dual Text Encoders:** Combines CLIP ViT-L and OpenCLIP ViT-bigG to interpret complex prompts and style cues.
* **Native Resolution:** Trained for $1024 \times 1024$ pixel output.
* **Precision:** FP16 (`torch.float16`) to reduce memory footprint by ~50% compared to FP32.


* **Distillation Acceleration:** `ByteDance/SDXL-Lightning` (`sdxl_lightning_4step_lora.safetensors`)
* **Progressive Adversarial Diffusion Distillation (ADD):** Reduces standard SDXL sampling from 20–50 steps down to **4 steps** without losing photorealistic details.
* **Fused LoRA Weight Injection:** Fused directly into the UNet tensor weights via `pipe.fuse_lora()`, eliminating LoRA adapter overhead during forward passes.


* **Fixing Black Image Bug:** `madebyollin/sdxl-vae-fp16-fix`
* Standard SDXL VAE causes numerical overflow under native FP16 on NVIDIA Turing architecture (T4 GPU), resulting in black or corrupted images.
* This custom VAE patch preserves FP16 precision across latent decoding while preventing numerical overflow.


* **Sampler / Scheduler:** `EulerDiscreteScheduler`
* Configured with `timestep_spacing="trailing"` to match the exact noise schedule required by SDXL-Lightning step trajectories.

## 4. Hardware & Optimization Stack

* **GPU Hardware:** NVIDIA Tesla T4 (16 GB VRAM, GDDR6, Turing Architecture).
* **Host Storage:** Ephemeral NVMe scratch disk mounted at `/mnt/fast-scratch` mapped to container `/data`.
* **PyTorch 2.x SDPA:** Native Scaled Dot-Product Attention eliminates the need for `xformers` while reducing attention memory overhead.
* **`torch.compile(mode="reduce-overhead")`:** Fuses PyTorch execution operators into optimized C++ / CUDA kernels. Cuts inference latency down to ~2 seconds per image after initial warmup.
* **Memory Slicing:** `enable_attention_slicing()` and `enable_vae_slicing()` prevent VRAM out-of-memory errors when processing multi-image batches.
* **In-Memory Streaming:** Images pass directly from GPU tensor output to standard PNG format inside a PyTorch `io.BytesIO` memory buffer. Bypasses host disk I/O and streams directly to AWS S3 (`viv-image-gen-presentation`).

Strict Instructions & User Override Handling

To ensure the Agent balances quality enhancements while respecting user constraints, we embed explicit Rule Priorities within the system prompt:

    User Override Rule: If the user specifies an explicit style, background, aspect ratio, camera angle, or subject restriction (e.g., "Make it line art, NO background"), the agent must strictly follow the user's explicit choices and not force photorealism or extra background elements.

    Context Enrichment Rule: If the user provides a vague or standard concept, the agent uses its CBSE curriculum background knowledge to build rich visual details.


    Prompt Enhancer Agent microservice designed to handle any subject domain (STEM, Humanities, Arts, Languages, everyday concepts) and transform raw user queries into rich, multi-layered SDXL prompts.
